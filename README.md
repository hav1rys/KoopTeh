# Расписание-бот — ЧПОУ «Кооперативный техникум» (Петрозаводск)

Discord-бот на **Node.js / discord.js**. Каждый день в заданное время присылает
студенту в личные сообщения расписание пар его группы на завтра. Источник —
страница-календарь `https://koopteh10.ru/student/lessons/` и Google-таблицы дня,
которые с неё выкладывают.

Вся настройка — через одну команду **`/start`**, которая открывает меню с кнопками.

---

## Команда и меню

| Команда  | Что делает                                              |
|----------|--------------------------------------------------------- |
| `/start` | Открывает личное меню (эфемерное, видно только тебе)    |

В меню:

- **Указать / сменить группу** — модальное окно, вводишь название (`209ИС-1`, `ИС1`, …).
  Сохраняется связка `discord_user_id → группа`, ежедневная рассылка сразу включается.
- **Расписание на завтра** — показать прямо сейчас.
- **На другую дату** — модальное окно, вводишь `дд.мм` или `дд.мм.гггг`.
- **Включить / отключить рассылку** — не теряя сохранённую группу.
- **Обновить** — перерисовать меню (текущая группа и статус подписки).

Расписание работает и без подписки — достаточно один раз указать группу.

---

## Ежедневная рассылка

Фоновая задача проверяет время раз в минуту и в `BROADCAST_TIME`
(по умолчанию **19:00**, пояс `TIMEZONE` = `Europe/Moscow`) для каждого
подписанного пользователя:

- заново скачивает страницу-календарь и нужную Google-таблицу (**без кэша**,
  всегда свежие данные на момент отправки; в рамках одного прогона одинаковые
  группы форматируются из уже скачанного CSV, чтобы не долбить Google);
- находит расписание на завтра для его группы и шлёт **в личку**;
- если ЛС закрыты — не падает, пишет в лог и пропускает пользователя;
- если на завтра расписание ещё не опубликовано — присылает короткое
  сообщение об этом, а не молчит;
- если сайт/таблица недоступны — сообщение «не удалось получить расписание,
  попробую позже» и запись в лог.

## Формат сообщения

```
Расписание на 02.09 (среда), группа 209ИС-1:
10:00–11:20 — МДК 02.01, Пашкевич Е.Л., ауд. 22
11:50–13:10 — Операционные системы, Ермаков И.С., ауд. 20
13:30–14:50 — пар нет
15:00–16:20 — Базы данных, Сидорова В.В., ауд. 21
```

- Внутренние «окна» показываются как `пар нет`; ведущие/замыкающие окна убираются.
- Совсем нет пар в этот день → одно сообщение `Пар нет`.
- Общекурсовые события (линейки, общие классные часы) помечаются `🔔`.

## Переменные окружения

| Переменная           | По умолчанию                                | Назначение                                  |
|----------------------|---------------------------------------------|---------------------------------------------|
| `DISCORD_BOT_TOKEN`  | —  (обязательна)                            | Токен бота из Discord Developer Portal      |
| `BROADCAST_TIME`     | `19:00`                                     | Время ежедневной рассылки, ЧЧ:ММ            |
| `TIMEZONE`           | `Europe/Moscow`                            | Часовой пояс IANA                           |
| `CALENDAR_URL`       | `https://koopteh10.ru/student/lessons/`     | Страница-календарь                          |
| `DATA_FILE`          | `data/users.json`                          | Файл-хранилище пользователей                |
| `GUILD_ID`           | пусто                                       | ID сервера для мгновенной регистрации `/start` при разработке |
| `HTTP_TIMEOUT`       | `20`                                        | Таймаут HTTP-запросов, секунды              |
| `LOG_LEVEL`          | `INFO`                                      | `DEBUG` / `INFO` / `WARN` / `ERROR`         |

Список для справки продублирован в [`.env.example`](.env.example).

## Развёртывание на BotHost (через GitHub)

1. **Сгенерировать `package-lock.json`** на машине с Node ≥18 (`npm install`) и
   закоммитить его. Без lock-файла сборочный шаг BotHost `npm ci` падает и
   уходит в запасной `npm install` — работает, но в логах красный `npm error`.
   С lock-файлом сборка чистая и воспроизводимая.
2. Залить репозиторий на GitHub.
3. В BotHost создать проект из GitHub-репозитория.
4. **Node.js версия:** 18 или новее (образ BotHost — `node:20-alpine`).
5. **Start command / файл запуска:** `npm start` (он же `node index.js`).
6. В панели проекта (Startup / Variables) добавить переменные окружения —
   минимум `DISCORD_BOT_TOKEN`, при желании `BROADCAST_TIME`, `TIMEZONE` и т.д.
   Файл `.env` в репозиторий класть не нужно.
7. `GUILD_ID` **не задавать** (нужен только для локального теста, см. ниже).
8. Запустить. В логах должно появиться `вошёл как <bot>#0000` и
   `команда /start зарегистрирована глобально (ЛС + User Install; ...)`.

> **Хранилище.** BotHost монтирует постоянный volume в `/app/data` и задаёт
> `DATA_DIR=/app/data`. `config.js` это учитывает: файл пользователей ляжет в
> `${DATA_DIR}/users.json` и переживёт перезапуски. Переопределить — `DATA_FILE`.

### Discord Developer Portal

- Создать приложение → **Bot**, скопировать **токен** в `DISCORD_BOT_TOKEN`.
- Привилегированные интенты **не нужны**.
- Бот работает **только в личных сообщениях**, на сервер вступать не обязан.
  Как сделать `/start` доступной в ЛС без сервера:
  1. **Installation** → **Installation Contexts** → включить **User Install**
     (и Guild Install можно оставить).
  2. **Installation** → **Install Link**: `Discord Provided Link` — по ней
     студент добавляет приложение себе в аккаунт.
  3. `GUILD_ID` в переменных окружения **оставить пустым**.
  Тогда бот при старте регистрирует `/start` глобально с типами установки
  `User Install` + `Guild Install` и контекстами `ЛС / личные группы / серверы`.
- Если User Install в портале не включён, регистрация с ним падает, и код
  **автоматически откатывается** на обычную глобальную команду (она видна в ЛС
  тем, у кого с ботом есть общий сервер). В логах будет строка `WARN … пробую
  обычную глобальную`.
- Быстрый тест: задать `GUILD_ID` = ID своего сервера → `/start` появляется на
  нём сразу (но только там). Для боевого режима переменную убрать.

## Локальный запуск

```bash
npm install
cp .env.example .env      # вписать DISCORD_BOT_TOKEN
npm start
```

Проверить парсер расписания без Discord:

```bash
node scheduleSource.js 209ИС-1 02.09.2026
```

Тесты парсинга (встроенный тест-раннер Node, без зависимостей):

```bash
npm test
```

## Ограничения парсинга

Формат Google-таблиц техникума нестабилен, парсер эвристический:

- **Колонка группы** ищется заново для каждого дня и каждого блока по названию
  группы в строке-заголовке (регистр, пробелы и `ё/е` игнорируются; ячейка с
  несколькими группами через запятую разбивается).
- **Общее событие на курс** засчитывается, когда в строке справа от столбца B
  заполнена ровно одна ячейка и это первая групповая колонка блока (так
  выглядит объединённая ячейка в CSV-экспорте).
- **Разбор строки пары** (`предмет / преподаватель / аудитория`) — по типовым
  шаблонам; если шаблон не подошёл, показывается исходный текст ячейки без
  ведущего номера пары.
- **Сопоставление даты в календаре** идёт по полной дате `дд.мм.гггг`, если она
  есть в тексте ссылки, иначе по номеру дня месяца. На стыке месяцев номер дня
  может быть неоднозначным — календарь техникума показывает текущий месяц.

Если техникум поменяет вёрстку страницы или структуру таблиц — правки в
`scheduleSource.js` (`extractSheetLinks`, `parseBlocks`, `buildEntries`,
`formatLesson`), тесты рядом.
